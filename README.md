## 6. Логирование и ELT процессы (Задание З05)

Создан автоматизированный SQL-скрипт загрузки данных `sql/load_and_check.sql`. Он реализует ELT-пайплайн по принципу: Полное пересоздание таблиц (Идемпотентность) -> Проверка качества (Data Quality) -> Загрузка измерений -> Загрузка фактов.

### Принцип идемпотентности:
При повторном запуске скрипта срабатывают команды `DROP TABLE IF EXISTS` и `CREATE TABLE`, которые полностью пересоздают структуру с нуля. Это гарантирует защиту от дублирования первичных ключей и **не раздувает факт при перезапусках**.

## 7. История справочника SCD Type 2 (Задание З06)

Для справочника товаров реализована модель **SCD Type 2** в скрипте `sql/scd2_demo.sql` (`dim_products_scd2`).

### Структура версионности (DDL):
В таблицу добавлены технические атрибуты:
- `product_sk` — суррогатный ключ конкретной версии записи;
- `valid_from` / `valid_to` — интервал дат действия версии;
- `is_current` — флаг актуальной записи.

### Как факт связывается с нужной версией:
При построении отчётов таблица фактов `fact_orders` соединяется со справочником по бизнес-ключу и попаданию даты заказа в интервал действия версии:
`ON f.product_id = p.product_id AND f.order_date BETWEEN p.valid_from AND p.valid_to`.

В демо-скрипте сыгран перенос товара `P01` с `2026-06-01` из категории **«Электроника»** в категорию **«Гаджеты»**: заказы до 31 мая учитываются в старой категории, а с 1 июня — в новой.
